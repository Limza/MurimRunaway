# Docs/AGENTS.md — 문서 작성 형식 규칙

`Docs/` 안의 `.md`를 쓰거나 고칠 때 자동 로드된다. 루트 [AGENTS.md](../AGENTS.md) §4 "인지 부하 3종" 원칙을 **문서 산문에** 적용한 규칙 + Obsidian Markdown 활용. 충돌 시 루트 AGENTS.md 우선.

전제: 이 저장소 문서는 **Obsidian으로 읽고 편집**한다. 출력 포맷은 항상 Markdown — HTML 금지(Obsidian 비호환·diff·공동 편집 손실).

---

## 1. 콜아웃 어휘 (고정 셋 — 늘리지 말 것)

일반 `>` 블록쿼트 금지. 모든 곁가지는 아래 7종 **타입 콜아웃**으로. 타입이 곧 "이걸 지금 읽어야 하나"의 신호다.

| 용도 | 타입 | 기본 |
|------|------|------|
| 문서 위상·메타·작성 규칙 | `[!abstract]` | 접힘 `-` |
| 근거·보충 설명 (왜 이렇게) | `[!note]` | 펼침 |
| 세부·버전 이력 (어쩌다 이렇게) | `[!info]` | 접힘 `-` |
| 미래 작업·리팩토링 트리거·함정 | `[!warning]` | 접힘 `-` |
| 반드시 지킬 규칙·진행 원칙 | `[!important]` | 펼침 |
| 네비게이션·범위 안내 | `[!tip]` | 펼침 |
| 코드 예·시나리오·요약 박스 | `[!example]` | 펼침 |

```
> [!note] 제목
> 본문. 콜아웃 안에서도 - 리스트, `코드`, **굵게** 다 됨.
```

---

## 2. 폴딩 규칙

콜아웃 헤더 접미사로 접힘 상태를 정한다.

- `[!type]-` — **지금 안 읽어도 되는 것**: 한 번 읽고 끝낼 메타, 미래 가정, 깊은 이력. 기본 접힘.
- `[!type]+` — 반드시 한 번 보되 그 뒤 접을 것. 접이식·기본 펼침.
- `[!type]` — 지금 읽어야 하지만 본문 흐름의 곁가지. 폴딩 없음.
- **본문의 핵심은 절대 콜아웃·폴딩으로 숨기지 않는다.** 폴딩은 동선 정리지 정보 은닉이 아니다.

---

## 3. 본문 vs 콜아웃 분리 (가장 중요 — ①② 해결)

포맷만으로는 안 풀리는 부분. 루트 §4 "처리 과부하"를 문서에 그대로 적용한다.

- **SSOT 본문에는 "지금 참인 것"만.** 왜(근거)·버전 이력·미래 가정·예외 정당화는 본문에서 빼내 `[!note]`/`[!info]`/`[!warning]` 콜아웃으로. 본문을 읽는 사람이 "현재 사실"과 "왜/언젠가"를 매 문단 구분하지 않게 한다.
- **한 문장이 동시에 요구하는 개념 3개 이하** (루트 §4와 같은 숫자). 교차 참조·버전 마커·괄호 이력이 한 문장에 4개 이상 엉기면 → 문장을 쪼개거나, 곁가지를 콜아웃으로 분리.
- 분리 판단: "이 문장이 *규칙/현재 사실*인가, *그 이유나 경위*인가?" 후자는 콜아웃.

## 4. 쉬운 말 우선

- 문서와 문서 안 코드 주석은 **쉬운 단어를 먼저 쓴다.**
- 수학·아키텍처·영어 관용어는 꼭 필요할 때만 쓴다.
- 독자가 뜻을 한 번 더 해석해야 하는 말은 풀어 쓴다.
  예: `payload` → `데이터`, `이산 사건` → `한 번 발생한 알림`.
- 어려운 용어가 SSOT나 코드 이름이라 꼭 필요하면, 처음 나올 때 쉬운 설명을 붙인다.

## 5. 작업 순서대로 쓰기

- Phase Guide는 **읽는 순서 = 작업 순서**가 되게 쓴다.
- 아직 만들지 않은 타입·필드·메서드를 쓰는 최종 코드를 앞에 두지 않는다.
- 최종 코드가 뒤 단계 산출물에 의존하면, 그 산출물이 만들어진 뒤의 절로 옮긴다.
- 어쩔 수 없이 미리 언급해야 하면 코드 블록이 아니라 짧은 안내 문장으로만 적는다.

## 6. 위키링크 & 노트 분할

- 저장소 내부 문서 참조는 `[[NoteName]]` 위키링크. (`[텍스트](경로.md)` 금지 — 호버 프리뷰·백링크·이동 손실)
- 외부 URL·문서 내 앵커는 `[텍스트](url)` 그대로.
- 한 노트가 길어 **선형 스크롤을 강요**하면(대략 독립적으로 읽히는 큰 단위 — 예: Phase 하나) 별도 노트로 쪼개고, 부모 노트는 `[[ ]]` 목록 = MOC(목차 노트)로 만든다.

## 6.5 다이어그램 (mermaid) — 보강만 원칙

옵시디언은 ```` ```mermaid ```` 를 네이티브 렌더링한다. 흐름·상태·의존은 글보다 그림이 인지 부하가 낮다.

- **펜스 코드블록 안의 ASCII/화살표 다이어그램**(`──` `▼` `│` `→` 로 그린 상태머신·플로우)은 mermaid로 **1:1 변환**한다. 노드·엣지·라벨을 원문 그대로 옮긴다 — 재해석·노드 추가 금지.
- **본문 산문·표 안의 인라인 `→`** (예: `Idle → HeavyCharging → Idle`)는 다이어그램이 아니다. 그대로 둔다.
- **합성 다이어그램 금지** — 본문 서술을 읽고 새로 그린 흐름도는 작성자 해석이 한 겹 끼므로 SSOT 문서에 넣지 않는다. 원문에 이미 그림(ASCII)이 있을 때만 mermaid화.
- 이 원칙의 상위 규칙: **기존 문서 전환은 "보강만"** — 포맷·다이어그램·콜아웃 분리는 하되 **본문 산문은 한 글자도 바꾸지 않는다**(§3의 근거 분리는 문장을 *옮기는* 것이지 *고쳐 쓰는* 것이 아니다).

## 7. 금지

- **콜아웃 남용 금지** — 깨끗이 읽히는 표·리스트는 그대로 둔다. 다 감싸면 ③(블록쿼트 인플레)이 재발한다.
- **타입 발명 금지** — §1의 7종만. 새 의미가 필요하면 규칙을 먼저 고친다.
- **베어 `>` 금지** — 인용이 정말 인용이면 `[!quote]`.
- **핵심 폴딩 금지** — §2 마지막 줄.

## 8. 적용 범위 & 마이그레이션

- `Docs/**/*.md`를 **새로 만들거나 고칠 때** 이 규칙 적용. 새 Phase Guide/Learned도 처음부터 이 형식.
- 기존 문서는 **손대는 김에 같이 전환**(opportunistic). 한 파일을 절반만 전환해 형식이 섞이지 않게, 건드린 문서는 그 세션에 끝까지 전환.
- 일괄 전환 우선순위가 필요하면: `BATTLE_DESIGN.md` → Phase Guide → 나머지. 일괄 작업은 별도 작업 단위로 잡는다.
