# Docs/AGENTS.md — 문서 작성 규칙

`Docs/**/*.md`를 만들거나 고칠 때 적용한다.
루트 [AGENTS.md](../AGENTS.md) §4 인지 부하 원칙을 문서 산문에도 적용한다.
충돌하면 루트 규칙이 우선이다.
문서는 Obsidian에서 읽는다.
출력은 Markdown만 사용하고 HTML은 쓰지 않는다.
---
## 1. 콜아웃

일반 `>` 블록쿼트는 금지한다.
곁가지는 아래 타입 콜아웃만 쓴다.

| 용도 | 타입 | 기본 |
|------|------|------|
| 문서 메타 | `[!abstract]` | 접힘 `-` |
| 근거·보충 | `[!note]` | 펼침 |
| 세부·이력 | `[!info]` | 접힘 `-` |
| 미래 작업·함정 | `[!warning]` | 접힘 `-` |
| 필수 규칙 | `[!important]` | 펼침 |
| 범위·동선 | `[!tip]` | 펼침 |
| 코드 예·요약 | `[!example]` | 펼침 |

- `[!type]-`: 지금 안 읽어도 되는 내용.
- `[!type]+`: 먼저 보되 나중에 접어도 되는 내용.
- `[!type]`: 지금 읽어야 하는 곁가지.
- 본문 핵심은 콜아웃이나 폴딩 안에 숨기지 않는다.
- 타입은 늘리지 않는다.

## 2. 본문과 콜아웃

- SSOT 본문에는 지금 참인 규칙과 사실만 둔다.
- 이유, 이력, 미래 가정, 예외 정당화는 콜아웃으로 뺀다.
- 한 문장이 동시에 다루는 개념은 3개 이하로 유지한다.
- 문장이 길어지면 문장을 나눈 뒤, 필요할 때만 개행한다.
- 본문·콜아웃 본문은 한 줄이 80자 안팎을 넘기면 자연스럽게 개행한다.
- 표, 코드 블록, 파일 경로, URL, 긴 링크 텍스트는 억지로 쪼개지 않는다.
---
## 3. 문장

- 쉬운 말을 먼저 쓴다.
- 영어 관용어, 수학 용어, 아키텍처 용어는 꼭 필요할 때만 쓴다.
- 어려운 용어가 코드 이름이나 SSOT 용어라면 처음에 짧게 설명한다.
- 문서 안 코드 주석도 같은 기준을 따른다.
---
## 4. Phase 문서

- 새 Phase 시작 시 Guide와 Learned를 함께 만든다.
- Guide는 작업 순서, 파일 위치, 최소 예제, 검증 조건을 담는다.
- Learned는 설계 이유, 용어 설명, 비교안, 나중에 볼 개념을 담는다.
- Guide의 긴 이유는 3문장 이하로 줄이고 `[[Phase_N_Learned]]`로 넘긴다.
- 같은 내용이 둘 다 필요하면 Guide에는 결론만, Learned에는 이유를 쓴다.

### Guide

- 읽는 순서가 작업 순서가 되게 쓴다.
- 첫 화면에 목표, 참조 SSOT, Non-goals, 작업 순서를 둔다.
- 아직 만들지 않은 타입·필드·메서드의 최종 코드를 앞에 두지 않는다.
- 한 절에는 되도록 하나의 행동만 둔다.
- 반복 필드와 설정값은 문장보다 표를 쓴다.
- 순서가 중요하면 numbered list를 쓴다.

### Learned

- 회고록이 아니라 오래 가져갈 학습 노트로 쓴다.
- 장기적으로 남길 개념을 5~10개 고른다.
- 한 절에는 하나의 핵심 질문만 둔다.
- 본문은 한 줄 뜻 → 왜 중요한가 → 이번 코드에서 어디에 보이나 순서로 쓴다.
- Anki 카드로 만들 가치가 낮은 구현 잡담, 커밋 사정, 임시 우회는 뺀다.

## 5. 예제 코드

- 예제 코드는 복사할 최종본보다 지금 고칠 조각을 우선한다.
- 새 타입처럼 파일 전체가 짧으면 완전한 예제를 둔다.
- 기존 파일을 고칠 때는 바뀌는 필드·메서드·블록만 보여준다.
- 아직 만들지 않은 helper나 타입에 의존하는 예제는 뒤로 옮긴다.
- 같은 패턴은 한 번만 자세히 쓰고 반복분은 체크리스트나 표로 줄인다.
- 코드 블록 앞에는 역할이나 지금 필요한 이유를 한두 문장으로 적는다.
---
## 6. 링크와 다이어그램

- 저장소 내부 문서는 `[[NoteName]]` 위키링크를 쓴다.
- 외부 URL과 문서 내 앵커는 Markdown 링크를 그대로 쓴다.
- ASCII/화살표 다이어그램이 이미 있으면 mermaid로 1:1 변환할 수 있다.
- 본문을 읽고 새 다이어그램을 합성하지 않는다.
- 인라인 `Idle → HeavyCharging → Idle` 같은 흐름 표기는 다이어그램이 아니다.
---
## 7. 금지와 마이그레이션

- 콜아웃 남용 금지. 깨끗한 표와 리스트는 그대로 둔다.
- 베어 `>` 금지. 인용이 필요하면 `[!note] 출처` 안에 짧게 둔다.
- 핵심 폴딩 금지.
- 기존 문서는 손대는 김에 형식을 맞춘다.
- 한 파일을 절반만 전환해 형식이 섞이게 두지 않는다.
- 일괄 전환 우선순위는 `BATTLE_DESIGN.md` → Phase Guide → 나머지다.
