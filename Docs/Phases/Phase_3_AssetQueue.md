## 1. M3 큐잉 시작점과 선행 완료의 정합

[[MILESTONES]] §3.1은 Track A 큐잉 시작을 **M3 진입 시점**으로 계획했다. 실제로는 AI 이미지 생성 대기시간을 코드 직렬 진행과 겹치지 않게 하려고 **Phase 1~2 동안 Track A를 선행 소진**했다(시안 1장+ 확보 기준 전 항목 충족).

따라서 M3 진입 시점의 Track A 상태:

- 계획: "M3부터 Track A 생성 시작"
- 실제: "M3 시점에 Track A 시안 확보 **이미 완료** → M3는 *큐잉 시작*이 아니라 *상태 확인·인계* 시점"

이 선행은 의도된 것이다(MILESTONES §1: *"AI 이미지 생성 대기로 코드가 멈추지 않도록 비동기 큐잉"*). 본 문서는 새 생성 작업을 **만들어내지 않는다** — 없는 일을 적는 건 큐의 목적이 아니다.

## 3. Phase 3에서 실제로 남은 일

Track A에서 **새로 생성해야 할 필수 이미지 에셋은 현재 없음**.

### 3.1 무공 슬롯 아이콘 (Phase 3 코드가 쓰는 것)

Phase 3 [[Phase_3_Guide]] §4 View의 슬롯 아이콘은 **단색 placeholder**로 Acceptance를 통과시킨다 — Track A의 정식 전투 아이콘과 별개다.

| 항목 | 처리 방식 | 메모 |
|------|-----------|------|
| 슬롯 무공 아이콘 (시작 3종) | 코드/UI placeholder | 단색 `Image` + 시전 시 `Id` 텍스트 1초. 정식 아이콘은 Phase 14 폴리시 |
| 쿨다운 오버레이 | 코드/UI 처리 | 반투명 `Image` 높이를 런타임 계산 (이미지 에셋 아님) |

> [!warning]
> 무공 아이콘을 Track A에 **새 항목으로 추가하지 않는다.** 정식 무공 일러스트/아이콘은 카드 시스템(Phase 12) + 모바일 UI(Phase 14) 진입 시 범위가 확정된다. 지금 큐에 박으면 범위 미정 상태의 죽은 항목.

[[Completed_Phase_2_AssetQueue]] §3와 동일.

1. 새 Track A 에셋 요청이 생기면 [[ASSET_PIPELINE]] §4 기준으로 시안 생성.

## 6. Phase 3 종료 시 인계

Track A 추가 요청이 안 생기면 본 문서도 **완료 기록 문서**로 유지한다(Phase 2와 동일 결).

이후 새 에셋 필요가 생기면:
- M5/M6/M8 실장 시점에 최종 픽 선정.
- 추가 수정이 필요한 항목만 재오픈.
- 코드 처리 항목과 이미지 제작 항목을 분리해서 기록.
- 무공 아이콘 정식 범위는 Phase 12(카드)/Phase 14(모바일 UI) 진입 시 확정 후 신규 트랙 항목으로 편성.
