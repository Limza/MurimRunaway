## 1. 왜 지금 미리 그리는가

[[MILESTONES]] §3.1:
- Track A "전투 아이콘"의 큐잉 시작 시점은 **M3 진입 시점**. Phase 1은 M3보다 앞서지만, 솔로 + AI 생성 환경에서 **2 Phase 앞당겨 시작**해도 손해 없음.
- 코드 Phase 1은 **S(작은 단위)**라서 한 작업 세션의 텀이 짧음. GPT 이미지 생성/수정은 수 분 단위로 반복되므로, 비는 시간에 시안을 계속 쌓기 좋음.
- 시안→수정→픽의 사이클이 2~4회 필요하므로 일찍 시작할수록 M5에서 비교 폭이 넓어짐.

## 2. GPT 기준 작업 원칙

1. **한 세션 = 한 카테고리**. 방어 아이콘 세션, hint 세션, 포트레이트 세션을 섞지 않는다.
2. **첫 괜찮은 결과를 기준 이미지처럼 삼고 같은 대화에서 이어 수정**한다.
3. **"새로 생성"보다 "같은 스타일 유지 + 특정 요소만 수정"** 지시를 우선한다.
4. **시안은 많이 저장하되 Final은 늦게 고른다**. 지금은 확보가 목적이다.
5. **작업 로그를 남긴다**. 어떤 프롬프트/수정 지시로 괜찮아졌는지 메모해두면 M5 이후 반복이 훨씬 빨라진다.

### 2.1 아이콘 프롬프트 작성 규칙

1. **막아야 하는 것은 "사람"이 아니라 "인물 중심 장면"**이다.
2. 아이콘은 `단일 중앙 심볼`, `단순 배경`, `작은 크기에서 읽히는 실루엣`을 우선한다.
3. 손, 발, 몸통 같은 **신체 일부 실루엣**은 허용할 수 있다. 다만 얼굴이 보이는 캐릭터 일러스트가 되면 실패다.
4. 스킬에 따라 두 템플릿을 구분한다.
5. `추상형`: 이화접목, 허실공처럼 문양·기류·상징이 잘 맞는 경우.
6. `신체 실루엣 허용형`: 보법, 나려타곤, 금강불괴처럼 발·몸통·자세 일부가 상징으로 유효한 경우.
7. 기본 톤은 **던파식 스킬 아이콘 문법**을 따른다. 작은 UI 크기에서 한눈에 읽히는 큰 중앙 심볼, 어두운 정사각형 배경, 높은 대비, 절제된 1~2색 포인트를 우선한다.
8. 무협 먹선과 붓결은 유지하되, **한 장의 그림**처럼 풀지 말고 **게임 스킬 아이콘**처럼 압축한다.
9. 유니티에서 별도 프레임 작업을 할 예정이므로, 이미지 안에 두꺼운 장식 프레임이나 완성형 UI 테두리는 넣지 않는다.
